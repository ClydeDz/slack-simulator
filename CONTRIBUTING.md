# Contributing to Slack Simulator

First off, thank you for considering contributing to this tool!

## 1. The Contributor License Agreement (CLA)

To protect the project's intellectual property and ensure we can safely maintain the codebase, we require all contributors to sign a Contributor License Agreement.

When you submit your first Pull Request, our CLA bot will automatically comment on it with a link. You simply need to click the link, authenticate with your GitHub account, and accept the agreement. **We cannot review or merge any Pull Requests until the CLA is signed.**

## 2. Local development setup

Refer to the [get started](./docs/get-started.md) page for setting up the Slack Simulator with your Slack App.

## 3. Creating a GitHub issue

Please start off by [creating a GitHub tracking issue](https://github.com/ClydeDz/slack-simulator/issues/new) and assign yourself to the issue for visibility. When making a PR, please link this issue to it. If there is a GitHub issue open, please do not duplicate it, instead, assign yourself to an existing open issue.

## 4. Submitting a pull request

- Keep your PRs focused on a single issue, bug fix, or feature.
- Provide a clear description in your PR explaining the _why_ behind your technical choices.
- Link an existing or new GitHub issue.
- Update the README if you are changing user-facing commands or configurations.
- Update the public docs in the docs folder to reflect any changes you've made.
